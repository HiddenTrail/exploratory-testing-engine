# EcoEstate Notes Oracle Value

A measurement experiment: does the oracle library (generated by
[ecoestate-notes-poc/run_oracle_pass.py](../ecoestate-notes-poc/run_oracle_pass.py)) change real
Driver+Skeptic outcomes on the notes CRUD API? Same paired-trial idea as
[token-purchase-oracle-value](../token-purchase-oracle-value) and
[pattern-detection-oracle-poc](../pattern-detection-oracle-poc), adapted to a script that owns a
real Node server's lifecycle rather than a mock Python SUT or a single-shot call.

5 paired trials (10 runs), 3 checkpoints x up to 7 tests each, oracle_library present in one arm's
casting+hypothesis evidence and absent from the other's - the Skeptic never sees it in either arm.
The EcoEstate server is restarted fresh before every individual trial.

Includes a fix for a real bug found live in `ecoestate-notes-poc`: the Driver repeatedly
miscounted its own intended-length boundary test strings (claiming "500 chars", actually sending
506-516) and treated the server's correct rejection as a bug. Every executed test now reports
`actual_content_length` back into evidence so later reasoning can check what was really sent.
Verified working in this run - see [REPORT.md](REPORT.md).

## Running it

```
pip install -r requirements.txt   # (or reuse ecoestate-notes-poc's env)
cp .env.example .env   # fill in ANTHROPIC_API_KEY
python run_comparison.py
```

Requires `../ecoestate-notes-poc/results/oracle_library.json` to already exist. Starts and stops
the EcoEstate server itself before/after every trial - port 3001 must be free before you run it.
Writes 10 full run directories plus `results/comparison_summary.json` under `results/`
(gitignored).

## Result

See [REPORT.md](REPORT.md). Short version: no measurable difference in raw bug yield once the
Driver's own length-miscounting artifacts are filtered out (0 genuine anomalies either arm), but a
real, repeatable, structurally oracle-only effect - 4/5 with-oracle trials independently tested
and refuted a stale tech-debt claim (`TD-2026-004`), and the one real open security gap
(`R-2026-006`, no ownership check on note mutation) was named in 5/5 with-oracle trials and 0/5
without - though never actually exercised by a live test in either case, since the API has no
session concept to construct that test against.
